# gtm-outbound

B2B outbound campaign engineering for Claude Code — nine skills, one research agent, six
local scripts, zero dependencies.

Engineers cold outbound as a dependency chain instead of a pile of tactics: strategy
constrains the data spec, the data spec constrains the copy, and each stage writes an
artifact the next stage validates against. A merge tag can never reference a field the
pipeline does not produce.

```
offer  ──► ICP-BLUEPRINT.md + icp.json
              └──► list ──► LIST-SPEC.md + clay-table.json
                              └──► copy ──► SEQUENCE.md + smartlead-config.json
```

## What it covers

| Stage | Owns |
|---|---|
| **offer** | Value Equation scoring, sub-niche narrowing, Sales Nav / Apollo filters, UVP hypotheses |
| **list** | Sourcing channels, Claygent prompts, waterfall enrichment, verification, jurisdiction compliance gate |
| **clay** | Clay table construction: column order, credit class (incl. Clay's dual-credit model), SPICE prompts |
| **copy** | Poke the Bear sequences, spintax + the 2026 reframe, deliverability config, multichannel tracks |
| **math** | List sizing, inbox/domain count, CAC, payback, A/B significance — always through the script, never in prose |
| **score** | 100-point pre-launch gate with hard gates that fail the campaign regardless of total |
| **diagnose** | Post-launch failure diagnosis routed by layer: infrastructure → list → offer → copy |
| **reply** | Reply classification, objection library, booking motion, suppression mechanics |

Plus dedicated references for GCC/MENA markets, buying committees, cold calling,
LinkedIn profiles, multichannel orchestration, AI-SDR positioning, and 2026
deliverability (tri-provider bulk-sender rules, warmup risk, open-rate demotion).

## Quick start

```bash
git clone https://github.com/MostaDaoud/gtm-outbound.git
cd gtm-outbound
python preflight.py        # verifies Python + runs every script + checks a calculation
./install.sh               # or: pwsh -File install.ps1
```

Then restart Claude Code and type `/gtm-outbound` — it asks one question and routes.

Full details, troubleshooting, and uninstall: [INSTALL.md](INSTALL.md).

## Design rules

- **The skill never sends.** It produces configurations and drafts; a human transmits.
  That boundary is deliberate.
- **All arithmetic goes through `scripts/gtm_math.py`.** A wrong list size looks exactly
  as plausible as a right one.
- **Every campaign passes the validators before it ships** — `validate_spintax.py`,
  `score_message.py`, `clay_taxonomy.py validate`.
- **Numbers are calibrated defaults, not laws.** Replace them with your own data as it
  accumulates.

## Repo layout

```
gtm-outbound/            orchestrator (nested: outer = package, inner = skill)
gtm-outbound-*/          the eight sub-skills
_evals/                  30 evals, activation collision tooling, fixtures
_charts/                 package map diagrams, regenerated by script
preflight.py             machine check: run before installing
install.sh / install.ps1 installers (backup, never overwrite)
```

## Verification

`preflight.py` tests rather than asserts — it executes all six scripts and verifies one
calculation returns the right answer. `_evals/collision_check.py` measures whether any
skill competes for the same prompts as something already installed:

```bash
python _evals/collision_check.py --installed ~/.claude/skills --candidate .
```
