# LinkedIn Lab Vault

Build and maintain a working Obsidian environment for LinkedIn Lab. The vault is a
navigation and production layer over the existing corpus, not a second copy of
the multi-million-word transcript store.

## Architecture

- `_generated/` contains rebuildable topic, course, source, theme, and health
  notes. Never ask the user to edit these files.
- `Dashboards/` contains generated navigation and a workflow canvas.
- `Workflows/`, `Templates/`, `Projects/`, `Inbox/`, and `Source Notes/` are
  user-owned. The builder seeds missing files but never overwrites them.
- `.obsidian/` uses core plugins only. No community plugin is required.
- `_meta/build-manifest.json` records every generated file and its hash.

## Build or refresh

Resolve this skill directory and the sibling `linkedin-lab` skill to absolute
paths. Point `--data-dir` at LinkedIn Lab's external `.linkedin-lab-data` directory.

```powershell
python scripts/build_vault.py `
  --linkedin-lab-dir /absolute/path/to/linkedin-lab `
  --data-dir /absolute/path/to/.linkedin-lab-data `
  --vault /absolute/path/to/linkedin-lab-Vault
```

The builder reads:

- `linkedin-lab/assets/corpus_index.json`
- `linkedin-lab/assets/library_manifest.json`
- `linkedin-lab/assets/mining/mining_report.json`
- `linkedin-lab/references/*.md`
- `.linkedin-lab-data/sources/catalog.json`, when present
- `.linkedin-lab-data/sources/manifest.json`, when present
- the live sibling `_transcripts/` tree, when present, for drift detection only

It does not edit those inputs or copy original books, PDFs, videos, OCR pages,
or raw transcripts into the vault.

## Validate

Run validation after every build:

```powershell
python scripts/validate_vault.py /absolute/path/to/linkedin-lab-Vault
```

Validation checks required files, internal wikilinks, generated-file hashes,
topic/course/source counts, builder inputs, and whether the live transcript
tree changed after the build. Treat a non-zero exit as incomplete work.

## Workflow

1. Run LinkedIn Lab's own `linkedin_lab.py doctor` before a refresh when the corpus or
   source catalog may have moved.
2. Build the vault from the current indexed artifacts.
3. Run `validate_vault.py`.
4. Open `LinkedIn Lab Dashboard.md` in Obsidian and confirm the live totals and
   navigation match the build report.
5. Report the vault path, counts, validation result, and any unavailable
   optional input.

## Safety and provenance

- Overwrite only files recorded as generated by the prior build or files under
  `_generated/` and `Dashboards/` that this builder owns.
- Seed editable files only when absent.
- Preserve source paths and source-index status; do not imply that an indexed
  source is independently fact-checked.
- Preserve LinkedIn Lab's citation and copyright boundaries. The vault points to
  the search system and distilled references; it does not republish courses or
  books.
- Do not promise that Obsidian search replaces `linkedin_lab.py search`. The CLI is
  the retrieval authority for raw passages and precise locators.

## Failure handling

- Missing corpus index, library manifest, mining report, or reference folder:
  stop with exit 2 and name the missing path.
- Missing external source catalog: build the course/reference vault and mark
  the source library as unavailable.
- Broken wikilinks or generated hash drift: return the validator findings and
  do not call the vault complete.
- A user-edited generated note: rebuild it from source. Move durable personal
  material into `Source Notes/` or `Projects/` first.

## Example requests and forward tests

- "Build an Obsidian vault from my current LinkedIn Lab library." Expect a new
  vault with live course, topic, source, and theme counts and zero validator
  findings.
- "I re-mined LinkedIn Lab; refresh the vault." Add a personal line to a project
  note before the run and confirm the line survives while generated hashes and
  totals update.
- "Check whether my LinkedIn Lab vault is healthy." Deliberately alter one
  generated note in a disposable fixture and confirm validation reports its
  hash drift without modifying the file.

## Output contract

Return:

1. The absolute vault path.
2. Counts for topics, courses, local sources, and mining themes.
3. The corpus lesson, word, and hour totals.
4. Validation status.
5. Any optional source input that was absent.
